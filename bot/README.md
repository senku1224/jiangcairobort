# 酱菜冒险者公会 · QQ 机器人（本机后端）

用 [NapCat](https://github.com/NapNeko/NapCatQQ)（OneBot v11）把 QQ 群和招募网站连起来。

能力分两档：
- **只读**（只配 publishable key 就能用）：`/招募`、`/网站`、`/帮助`。
- **写入**（需要 `SUPABASE_SERVICE_KEY`，在网站完成 QQ 绑定后可用）：`/绑定`、`/报名`、`/取消`、`/我的`。

没配写入密钥时，写入类指令会明确回「未配置写入密钥」，**不会假装成功**。

## 它怎么工作

```
QQ 群 ──消息──▶ NapCat ──HTTP 上报──▶ 本机 bot（本目录）
                                        │
                                        ├─ 读：Supabase REST（publishable key，受 RLS 约束）
                                        ├─ 写：Supabase REST（service key，用于绑定/报名/取消）
                                        └─ 回：调用 NapCat HTTP API 发消息
```

零 npm 依赖，只用 Node 内置模块。默认监听 `127.0.0.1:8790`。

## 身份是怎么确认的（信任链）

1. 你在网站「冒险者名片」里点「生成绑定码」，得到 **6 位一次性绑定码**（10 分钟有效）。
2. 你在群里发给机器人：`/绑定 123456`。
3. 机器人拿到的 `user_id` 就是**你的真实 QQ 号**（NapCat 从 QQ 登录会话取得，用户改不了），
   用它核销绑定码，把 QQ 号写进你在网站的那份档案。
4. 之后 `/报名`、`/取消`、`/我的` 都用这个 QQ 号认人，**只操作用户自己的数据**。
   昵称只是显示用，永远不作为身份依据。

## 一、准备 NapCat

1. 到 NapCat 官方 Release 下载 **Windows 版**（一键包），解压启动。
2. 打开 NapCat 的 WebUI，用**手机 QQ 扫码登录**（建议用小号，别用常用大号）。
3. 在 WebUI 的「网络配置」里加两项：
   - **HTTP 服务器**：端口 `3000`（Token 可留空或自设，需与 `.env` 一致）——供本机 bot 发消息。
   - **HTTP 客户端 / 上报**：URL 填 `http://127.0.0.1:8790/onebot`，消息格式选 **array**，勾选上报群消息。
4. 把机器人小号拉进目标 QQ 群（或群主邀请）。

## 二、配置并启动本机后端

```bash
cd bot
cp .env.example .env      # 按需修改（QQ 群号、Token、服务端密钥等）
cd ..
npm run bot
```

看到「机器人后端已启动」即可。在群里 **@机器人 /招募** 或直接发 **/招募** 试试。

`.env` 已被 `.gitignore` 忽略，不会上传仓库。

### 让写入生效：填 SUPABASE_SERVICE_KEY

1. Supabase 控制台 → **Project Settings → API** → 找到 **`service_role`**（标着 secret）那一行，复制。
2. 粘贴到本机 `bot/.env` 的 `SUPABASE_SERVICE_KEY=` 后面。
3. 重启 `npm run bot`。

> ⚠️ service_role key 等于数据库的万能钥匙：**只放本机 `bot/.env`**，绝不写进前端、绝不提交仓库、绝不发到聊天里。
> 它让机器人能绕过 RLS 写库，因此机器人必须自己判断"是谁、能不能做"——代码里用 QQ 号认人，不信任用户传来的任何身份字段。

## 三、指令一览

| 指令 | 说明 | 需要写入密钥 |
| --- | --- | --- |
| `/招募` | 列出当前开放中的招募（游戏、时间、剩余席位） | 否 |
| `/网站` | 返回招募网站链接 | 否 |
| `/帮助` | 指令说明 | 否 |
| `/绑定 <码>` | 用网站生成的 6 位码把 QQ 绑定到你的身份 | 是 |
| `/报名 <序号>` | 报名第 N 份委托（序号见 `/招募` 列表） | 是 |
| `/取消 <序号>` | 取消自己的报名 | 是 |
| `/我的` | 查看我发布的和我报名的 | 是 |

报名仍受数据库触发器约束（满员、已截止会被拒绝），机器人只是替你在前端之外发起同样的写入。

## 四、网络与缓存兜底

本机网络有时连不上 Supabase（Cloudflare 被重置）。为此机器人：

- 支持经 HTTP 代理访问（在 `.env` 设 `BOT_PROXY`，或系统代理环境变量），并在抖动时自动重试 4 次。
- 每次 `/招募` 成功读取后，会把结果缓存到 `bot/data/quests-cache.json`（已被 gitignore）。
- 读取失败时，自动用**上次成功的缓存**回复，并标注「⚠️ 当前网络读取失败，以下为缓存数据，可能不是最新」；完全无缓存时才回退为报错提示。

注意：缓存只能让 `/招募` 在断网时**降级可用**，数据不是实时的。写入类指令（`/绑定`、`/报名`）必须联网，断网会直接失败并告知。`/帮助`、`/网站` 不依赖数据库，任何时候都能用。

## 五、保持运行

机器人是常驻进程，**本机关机 / 睡眠就下线**。想让它在群里一直在线，需要一台常开设备（自己长期开机的电脑，或便宜的小云服务器）。开机自启可用 Windows「任务计划程序」。

## 六、安全边界（重要）

- 机器人以事件里的 **QQ 号** 为准，绝不信昵称；未绑定的用户不能用写入类指令。
- 只读用 publishable key；写入才用 service key，且只放本机 `.env`。
- NapCat 是第三方方案，登录真实 QQ 号有**风控封号风险**，用小号、控制频率。
